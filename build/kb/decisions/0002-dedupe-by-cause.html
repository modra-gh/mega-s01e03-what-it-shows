0002 · Triage by demonstrated cause and input contract

owner modra-gh proposed reviewed 2026-10-29 · 0 days ago

Context

Decision 0001 accepted subject-only merging. The executable examples and the reports in the review contradict that rule. This record proposes its replacement; the desk must accept it before treating it as policy.

Proposed decision

Merge reports only when their demonstrated failure mechanism and expected behavior agree. Look up tenant locale, booking form, and channel; read the body; reproduce the relevant input path. Use the supplied cause model as evidence, and investigate when report details disagree with it. Treat intake tags and matching subjects as search aids only.

Keep unknown tenants and unexplained timing symptoms separate for investigation. Count distinct report IDs once. Record received and merged timestamps separately, preserving their offsets. Update guidance when new evidence changes the finding.

Consequences

Triage takes more reading but avoids hiding unrelated bugs behind one known issue. Keep separate engineering tickets for the shared parser and the booking-v3 hint, linked from the review. The old accepted record is preserved rather than rewritten. No fix or desk approval is claimed by this proposal.
